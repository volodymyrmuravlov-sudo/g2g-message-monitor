# G2G message monitor

Проверяет раз в 5 минут, не появилось ли новых сообщений в чате G2G, и
присылает алерт в Telegram. Работает на GitHub Actions (бесплатно —
репозиторий публичный, значит безлимитные Actions-минуты; секреты
зашифрованы и никому не видны).

**Приватность:** `state.json` коммитится в git-историю на каждом запуске.
Он хранит только SHA-256 хеши (имя + текст + время сообщения), никогда
сам текст переписки — иначе реальные диалоги с покупателями были бы видны
всем в публичном репозитории. По той же причине скрипт не сохраняет и не
загружает скриншоты/HTML страницы как артефакты — только Telegram-алерт
(приходит лично вам) содержит текст сообщения.

## Как это работает

1. `scripts/check_messages.py` открывает страницу чатов G2G
   (`https://www.g2g.com/chat/#/`) через Playwright, используя сохранённую
   сессию (cookies + localStorage) — без ввода логина/пароля.
2. Считывает счётчик `chatUnread` из localStorage и отпечатки (SHA-256
   хеши от имени + текста + времени) всех видимых диалогов в списке,
   сравнивает с тем, что сохранено в `state.json` при прошлой проверке.
3. Если счётчик вырос или у диалога изменился отпечаток — значит пришло
   новое сообщение (неважно, поднялся диалог наверх списка или нет) —
   шлёт алерт в Telegram с именем отправителя и текстом сообщения.
4. `state.json` коммитится обратно в репозиторий после каждого запуска —
   это заодно поддерживает репозиторий "живым", чтобы GitHub не отключил
   cron через 60 дней бездействия. В файле хранятся только хеши, не текст
   переписки.

## Настройка (нужно сделать один раз)

### 1. Secrets репозитория

Settings → Secrets and variables → Actions → Secrets → New repository secret:

| Имя | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен вашего Telegram-бота |
| `TELEGRAM_CHAT_ID` | `7509142413` |
| `G2G_COOKIES_JSON` | см. пункт 2 ниже |
| `G2G_LOCAL_STORAGE_JSON` | см. пункт 2 ниже |

G2G хранит основной токен авторизации не в cookies, а в localStorage
браузера — поэтому нужны оба секрета вместе, одних cookies недостаточно.

### 2. Экспорт сессии G2G (cookies + localStorage)

1. Установите расширение **Cookie-Editor** в браузер (Chrome/Edge).
2. Зайдите на https://www.g2g.com/chat/#/ и авторизуйтесь обычным способом.
3. **Cookies:** нажмите на иконку Cookie-Editor → **Export** → **Export as
   JSON** (копируется в буфер обмена) → вставьте как секрет
   `G2G_COOKIES_JSON`.
4. **localStorage:** нажмите F12 → вкладка **Console** → кликните в
   консоль → введите:
   ```
   copy(JSON.stringify(localStorage))
   ```
   → Enter (если браузер попросит — сначала наберите `allow pasting` и
   Enter, затем повторите команду) → вставьте как секрет
   `G2G_LOCAL_STORAGE_JSON`.

Когда сессия протухнет, бот сам напишет в Telegram "сессия истекла" — тогда
просто повторите эти шаги и обновите оба секрета.

### 3. Variables репозитория (адрес чата)

Settings → Secrets and variables → Actions → **Variables** → New repository variable:

| Имя | Значение |
|---|---|
| `G2G_INBOX_URL` | `https://www.g2g.com/chat/#/` (уже установлено) |

Селекторы для строк диалогов зашиты прямо в скрипт (`.g-channel-item--main`,
`.g-channel-item--side`) — это подтверждённая структура реальной страницы
G2G, отдельно настраивать не нужно. Если G2G когда-нибудь обновит вёрстку
чата и бот перестанет находить диалоги — придёт алерт в Telegram об этом,
и селекторы нужно будет один раз обновить в `scripts/check_messages.py`.

## Проверка

Actions → "G2G message check" → Run workflow — запускает проверку прямо
сейчас, не дожидаясь расписания. Смотрите лог шага "Check G2G messages".

## Если бот перестал писать

Скорее всего, истекла сессия — придёт алерт "сессия истекла" в Telegram.
Обновите `G2G_COOKIES_JSON` (пункт 2) и всё продолжит работать само.
